# ERN Integration Guide

This document covers everything needed to replicate the ERN (Engineering Request Number) integration from the ECR-Form project into a new project. It maps every SharePoint column, explains how ERNs are loaded and created, and documents all the UI components involved.

> **SmartBid disclaimer:** Concepts like **ECO**, **ECR**, **ECO Owner**, **ECO Creator**, and **Change Analyst/Specialist** are **specific to the ECR-Form project** and do not exist in SmartBid. Throughout this document those terms appear purely as examples of _how_ the ERN fields were populated in ECR-Form. In SmartBid you will need to map your own project's equivalent data (users, record identifiers, context) to the same ERN SharePoint columns. The column names and SP API calls are fully reusable; the business logic around who fills what and when is not.

## 1. SharePoint List Reference

| Property              | Value                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------- |
| **Site URL**          | `https://oceaneering.sharepoint.com/sites/G-OPGSSRBrazilEngineering`                          |
| **List relative URL** | `/sites/G-OPGSSRBrazilEngineering/Lists/Engineering Requestt`                                 |
| **List name**         | `Engineering Requestt` (note the double **"t"** — this is the actual list name in SharePoint) |
| **Access pattern**    | Same-site — use standard `getbytitle()` or `GetList()` endpoint                               |

> **SmartBid context:** The SmartBid app runs on the same SharePoint site as the ERN list (`G-OPGSSRBrazilEngineering`), so no cross-site configuration is needed. In the ECR-Form project the list was accessed cross-site (the app lived on a different site), which required using `GetList('encodedRelativeUrl')` and hardcoding the ERN site URL as a separate constant. In SmartBid you can simplify this by using the app's own `siteUrl` and the standard `getbytitle('Engineering Requestt')` endpoint.

## 2. Column Mapping

### 2.1 Reading ERNs (`IErn`)

These are the columns selected when loading ERNs from SharePoint (`$select=...`).

| Interface Field   | SP Internal Name | Description                                                                    |
| ----------------- | ---------------- | ------------------------------------------------------------------------------ |
| `Title`           | `Title`          | ERN Number (e.g. `ERN-42`)                                                     |
| `Status`          | `field_1`        | Current status (e.g. `Open`, `Completed`, `On Hold`)                           |
| `DueDate`         | `field_4`        | Engineering Due Date                                                           |
| `FinishDate`      | `FinishDate`     | Released / Finish Date                                                         |
| `ProjectTitle`    | `ProjectTitle`   | Project Title                                                                  |
| `ProjectNumber`   | `field_14`       | Project Number                                                                 |
| `Description`     | `field_2`        | Detailed Deliverable Description                                               |
| `DeliverableType` | `field_20`       | Deliverable Type (multi-select choice — returned as array, joined with `", "`) |

**OData query used:**

```
$select=Title,field_1,field_4,FinishDate,ProjectTitle,field_14,field_2,field_20
$top=5000
```

### 2.2 Creating ERNs (`IErnCreateData`)

All fields sent when creating a new item in the list. The `Title` (ERN number) is auto-generated by the service.

#### Page 1 — Request Info

| Field            | SP Internal Name | Value / Source                                                                                     |
| ---------------- | ---------------- | -------------------------------------------------------------------------------------------------- |
| Type of Request  | `field_12`       | Hardcoded `"Project"`                                                                              |
| Service Line     | `ServiceLine`    | Choice — loaded dynamically from list field choices                                                |
| Content Action   | `field_28`       | `"Create"` or `"Revise"`                                                                           |
| Revision Reason  | `RevisionReason` | Only when `field_28 = "Revise"` (see options below)                                                |
| Project Number   | `field_14`       | Auto-filled from ECO/ECR context _(ECR-Form only — in SmartBid, source this from your own record)_ |
| Project Name     | `field_15`       | Free text                                                                                          |
| Project Title    | `ProjectTitle`   | Free text (defaults to ECO title)                                                                  |
| Deliverable Type | `field_20`       | Choice — loaded dynamically; **must be sent as an array** `[value]`                                |

#### Page 2 — Schedule & Resources

| Field                   | SP Internal Name | Value / Source                                                                           |
| ----------------------- | ---------------- | ---------------------------------------------------------------------------------------- |
| Eng Due Date            | `field_4`        | ISO date string                                                                          |
| Checker Due Date        | `CheckerDueDate` | ISO date string                                                                          |
| Lead Date               | `LeadDate`       | ISO date string                                                                          |
| Resource 1 (name)       | `Resource1`      | ECO Owner display name _(ECR-Form role — in SmartBid, map to your own responsible user)_ |
| Resource 1 (email)      | `EmailResource1` | ECO Owner email                                                                          |
| Checker (name)          | `Resource3`      | Change Analyst display name _(ECR-Form role — adapt in SmartBid)_                        |
| Checker (email)         | `EmailChecker`   | Change Analyst email                                                                     |
| Lead (name)             | `Lead`           | Same as Checker                                                                          |
| Lead (email)            | `LeadEmail`      | Same as Checker                                                                          |
| Deliverable Description | `field_2`        | Free text                                                                                |

> **Note on `field_20` (Deliverable Type):** Even when it is a single value, it must be wrapped in an array in the POST body: `"field_20": ["Drawing"]`.

> **SmartBid note:** The resource fields (`Resource1`, `Resource3`, `Lead`) are required by the ERN list schema. There is no ECO Owner or Change Analyst in SmartBid — just decide which users from your own context are the responsible parties and pass their names/emails to those fields.

## 4. ERN Auto-Numbering

When creating a new ERN, the service does **not** pre-define the ERN number. Instead it:

1. Queries the last item in the list (`$orderby=Id desc&$top=1`).
2. Parses its `Title` to extract the trailing number (`ERN-(\d+)`).
3. Increments by 1 → `ERN-{n+1}`.
4. Uses that as the `Title` in the POST body.

```ts
// Example pattern
const match = items[0].Title.match(/ERN-(\d+)/);
nextNumber = parseInt(match[1], 10) + 1;
const ernTitle = `ERN-${nextNumber}`;
```

## 5. Service Interface (`IErnService`)

```ts
export interface IErnService {
  getAll(): Promise<IErn[]>;
  search(query: string): Promise<IErn[]>;
  create(data: IErnCreateData): Promise<IErn>;
  getFieldChoices(fieldInternalName: string): Promise<string[]>;
}
```

| Method                               | Description                                                                        |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| `getAll()`                           | Fetches all ERNs from the list (top 5000)                                          |
| `search(query)`                      | Calls `getAll()` then filters in-memory by Title, ProjectTitle, and Description    |
| `create(data)`                       | Auto-numbers and POSTs a new item to the SharePoint list                           |
| `getFieldChoices(fieldInternalName)` | Reads a SharePoint field's `Choices` array — used for `ServiceLine` and `field_20` |

**`getFieldChoices` API call:**

```
GET {siteUrl}/_api/web/GetList('{encodedListUrl}')/fields
    ?$filter=InternalName eq '{fieldInternalName}'
    &$select=Choices
```

## 6. Draft ERN System (localStorage)

Before an ECO is promoted to "In Work" and the ERNs are actually submitted to SharePoint, ERNs exist as **drafts in `localStorage`**. This allows the user to create and edit ERNs during the draft phase without touching the production list.

### Storage key format

```
ECR_DRAFT_ERNS_{ecoNumber}
```

Example: `ECR_DRAFT_ERNS_ECO-2026-0001`

### Draft ERN shape (`IDraftErn`)

```ts
interface IDraftErn {
  draftId: string; // "ERN-Draft-1", "ERN-Draft-2", ...
  ecoNumber: string; // The ECO this draft belongs to
  data: IErnCreateData; // Full creation payload
  createdAt: string; // ISO timestamp
}
```

### Helper functions (from `draftErnStorage.ts`)

| Function                             | Description                                             |
| ------------------------------------ | ------------------------------------------------------- |
| `getDraftErns(ecoNumber)`            | Returns all drafts for an ECO                           |
| `saveDraftErn(ecoNumber, draft)`     | Appends a draft to localStorage                         |
| `removeDraftErn(ecoNumber, draftId)` | Removes a single draft by id                            |
| `clearDraftErns(ecoNumber)`          | Clears all drafts (call after promoting ECO to In Work) |
| `getNextDraftId(ecoNumber)`          | Returns next sequential id: `ERN-Draft-{n+1}`           |

### Draft lifecycle

1. User opens `ErnCreateModal` → fills form → clicks "Create Draft ERN".
2. Data is saved to `localStorage` as `ERN-Draft-N`.
3. Draft appears in `ErnSearchModal` with a yellow "Draft" badge.
4. When ECO is promoted to "In Work", `clearDraftErns()` is called and the actual `IErnService.create()` is invoked to write to SharePoint _(ECR-Form specific — in SmartBid, define your own trigger for when drafts are committed to SharePoint)_.

## 7. React Hook (`useErn`)

A convenience hook that wraps `ernService` from context:

```ts
const { erns, loading, error, loadAll, search } = useErn();
```

| Return          | Type                           | Description                              |
| --------------- | ------------------------------ | ---------------------------------------- |
| `erns`          | `IErn[]`                       | Currently loaded ERNs                    |
| `loading`       | `boolean`                      | True while a request is in flight        |
| `error`         | `string \| undefined`          | Error message if the last request failed |
| `loadAll()`     | `() => Promise<void>`          | Loads all ERNs via `ernService.getAll()` |
| `search(query)` | `(q: string) => Promise<void>` | Filters ERNs via `ernService.search()`   |

## 8. UI Components

### 8.1 `ErnSearchModal`

**Location:** `components/EcoForm/sections/ErnSearchModal.tsx`

**Purpose:** Let the user pick an existing (or draft) ERN to link to an ECO.

**Props:**

| Prop             | Type                  | Description                                       |
| ---------------- | --------------------- | ------------------------------------------------- |
| `isOpen`         | `boolean`             | Controls modal visibility                         |
| `onDismiss`      | `() => void`          | Close callback                                    |
| `onSelect`       | `(ern: IErn) => void` | Called when the user clicks "Select"              |
| `onCreateNew`    | `() => void`          | Called when the user clicks "Create New ERN"      |
| `excludeTitles?` | `string[]`            | ERN Titles already linked — excluded from results |
| `ecoNumber?`     | `string`              | Used to load draft ERNs from localStorage         |

**Key behaviour:**

- Loads all ERNs on every open (uses a `ref` counter to prevent stale updates).
- Filters out `Status === "Completed"` items by default.
- Applies `excludeTitles` to prevent duplicate links.
- Sorts descending by ERN number (numeric).
- Renders draft ERNs first, with a yellow "Draft" badge.
- Client-side search across `Title`, `ProjectTitle`, `ProjectNumber`, `Description`.

---

### 8.2 `ErnCreateModal`

**Location:** `components/EcoForm/sections/ErnCreateModal.tsx`

**Purpose:** Two-page wizard to create a new draft ERN.

**Props:**

| Prop                 | Type                                            | Description                                                                                          |
| -------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `isOpen`             | `boolean`                                       | Controls visibility                                                                                  |
| `onDismiss`          | `() => void`                                    | Close callback                                                                                       |
| `onCreated`          | `(ernTitle: string, ernStatus: string) => void` | Called after successful save                                                                         |
| `projectNumber`      | `string`                                        | Auto-filled from ECO context _(ECR-Form specific — source from SmartBid's own record)_               |
| `ecoTitle`           | `string`                                        | Default value for Project Title field _(ECR-Form specific — adapt to SmartBid's context)_            |
| `ecoNumber`          | `string`                                        | Used as the draft storage key _(ECR-Form specific — use SmartBid's own record identifier)_           |
| `defaultDescription` | `string`                                        | Default Deliverable Description                                                                      |
| `ecoOwnerName`       | `string`                                        | Resource 1 name _("ECO Owner" is ECR-Form terminology — map to SmartBid's equivalent user)_          |
| `ecoOwnerEmail`      | `string`                                        | Resource 1 email                                                                                     |
| `ecoOwnerPhotoUrl`   | `string`                                        | Resource 1 avatar                                                                                    |
| `checkerName`        | `string`                                        | Checker / Lead name _("Change Analyst" is ECR-Form terminology — map to SmartBid's equivalent user)_ |
| `checkerEmail`       | `string`                                        | Checker email                                                                                        |
| `checkerPhotoUrl`    | `string`                                        | Checker avatar                                                                                       |
| `editDraftId?`       | `string`                                        | If provided, edits an existing draft instead of creating a new one                                   |

**Page 1 fields:** Type of Request, Service Line, Content Action, Revision Reason (conditional), Project Number (read-only), Project Name, Project Title, Deliverable Type.

**Page 2 fields:** Eng Due Date, Checker Due Date, Lead Date, Resource 1 (read-only persona), Checker (read-only persona), Lead (read-only persona), Deliverable Description.

**On submit:** Saves to `localStorage` as a draft (does not call SharePoint). Calls `onCreated(draftId, "Draft")`.

> **SmartBid note:** The form logic and two-page wizard are fully reusable. What needs adapting is: the prop names (drop the `eco`/`checker` terminology), the draft storage key (use SmartBid's own record identifier instead of `ecoNumber`), and the trigger for when drafts are finally submitted to SharePoint (there is no ECO "promote to In Work" step in SmartBid).

### 8.3 `ErnsDetailedModal`

**Location:** `components/EcoList/ErnsDetailedModal.tsx`

**Purpose:** Read-only table showing all ERNs linked to a given ECO.

**Props:**

| Prop        | Type         | Description                            |
| ----------- | ------------ | -------------------------------------- |
| `eco`       | `IEcoItem`   | The ECO whose ERNs are being displayed |
| `isOpen`    | `boolean`    | Controls visibility                    |
| `onDismiss` | `() => void` | Close callback                         |

> **SmartBid note:** `ErnsDetailedModal` is **highly ECR-Form-specific** in its data-loading logic — it depends on `IEcoItem`, `ecoAffectedItemsService`, ECR IDs, and the ECO number, none of which exist in SmartBid. Use it as a reference for the table layout only. In SmartBid, replace the loading logic with a simpler approach: store the linked ERN titles in your own record, then call `ernService.getAll()` and filter by those titles.

**Data loading logic (ECR-Form reference only):**

1. Fetches `IEcoAffectedItem` records via `ecoAffectedItemsService.getByEcrIds(eco.RelatedEcrIds)` (ECR-imported items).
2. Also fetches via `ecoAffectedItemsService.getByEcoNumber(eco.EcoNumber)` (draft-originated items).
3. Deduplicates by `Id`.
4. Extracts all `ErnTitle` values from the merged list.
5. Calls `ernService.getAll()` and filters to only the matching titles.

**Displayed columns:** ERN Number, Status, Deliverable Type, Due Date, Released Date, Project Title, Deliverable Description.

## 9. Service Instantiation

In the main app component (`EcrForm.tsx`), the service is instantiated once and injected via React context:

```ts
// Production (SharePoint)
ernService: new SpErnService(props.spHttpClient!, props.siteUrl!);

// Local dev / mock
ernService: new JsonErnService();
```

> **ECR-Form note:** In ECR-Form, `SpErnService` hardcoded `ERN_SITE_URL` and ignored the `siteUrl` constructor argument because the list lived on a different site. **In SmartBid**, since both app and list share the same site, pass `siteUrl` normally and replace the hardcoded `ERN_SITE_URL` / `ERN_LIST_RELATIVE_URL` constants with `${siteUrl}/_api/web/lists/getbytitle('Engineering Requestt')/...`.

## 10. Wiring Into a New Project

Minimum steps to replicate this integration:

1. **Copy the interfaces:**
   - `src/models/IErn.ts` → defines `IErn` and `IErnCreateData`.

2. **Copy the service:**
   - `IErnService` interface from `IDataService.ts`.
   - `SpErnService` class from `SharePointDataService.ts`.
   - **SmartBid:** Remove the `ERN_SITE_URL` / `ERN_LIST_RELATIVE_URL` constants. Replace every `GetList('encodedRelativeUrl')` call with `${siteUrl}/_api/web/lists/getbytitle('Engineering Requestt')` using the app's own `siteUrl`.

3. **Copy the draft storage helper:**
   - `src/helpers/draftErnStorage.ts` — pure localStorage helpers, no dependencies.

4. **Expose via context:**
   - Add `ernService: IErnService` to your app context.
   - Instantiate `SpErnService` where you build the context value.

5. **Copy UI components as needed:**
   - `ErnSearchModal` + `ErnSearchModal.module.scss`
   - `ErnCreateModal` + `ErnCreateModal.module.scss`
   - `ErnsDetailedModal` + `ErnsDetailedModal.module.scss`

6. **Update imports** in the components to match the new project's folder structure.

7. **Load field choices on open** — both `ServiceLine` and `field_20` (Deliverable Type) must be fetched dynamically via `ernService.getFieldChoices(fieldInternalName)` because they are SharePoint choice fields.

## 11. Type Reference

```ts
// IErn — read from SharePoint list
export interface IErn {
  Title: string; // ERN Number

  ProjectTitle?: string;
  ProjectNumber?: string; // field_14
  Description?: string; // field_2

// IErnCreateData — written to SharePoint list
export interface IErnCreateData {
  // Page 1
  field_12: string; // "Project"
  ServiceLine: string;
  field_28: string; // "Create" | "Revise"
  RevisionReason?: string; // only when field_28 = "Revise"
  field_14: string; // Project Number
  field_15: string; // Project Name

  Resource1: string; // ECO Owner name
  EmailResource1: string; // ECO Owner email
  Resource3: string; // Checker name
  EmailChecker: string; // Checker email

}
```
